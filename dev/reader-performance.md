Reader dependency change and performance
========================================

The FASTA and GFF readers now use `widen_attributes()` instead of
`tidyr::pivot_wider()`. The helper uses base R for reshaping and the existing
dplyr dependency to retain the previous tibble return type. It preserves
first-seen record/field order, missing values, non-syntactic names and duplicate
keys (warning and list columns). Invalid output names still fail.

tidyr has moved from Imports to Suggests because the FASTA tutorial still uses
`tidyr::separate_rows()`. It is no longer imported or required by the readers.
The installed runtime dependencies of htmlwidgets, dplyr and fontawesome do not
require tidyr, stringr, stringi or purrr in the environment used for this review.
The dashboard needs rebuilding with the updated package before its download
manifest can be checked for the expected removal of those packages.

Benchmarks, 2026-10-26
----------------------

Native R 4.4.0 on macOS arm64, tidyr 1.3.1 and Biostrings 2.74.1. Seven
repetitions per implementation, alternating measurement order. These are median
elapsed times with packages already loaded and filesystem caches warm. Small
operations were batched to reduce timer quantization. No other benchmark was
run concurrently. The old implementation uses exactly the same reader code,
with only the new metadata helper replaced by the previous pivot operation.
Every benchmark checks identical complete outputs before measuring.

| Complete file load | Previous | Helper | Difference |
| --- | ---: | ---: | ---: |
| Packaged GFF example | 176 ms | 175 ms | -0.6% |
| genomic.gff (about 2.5 MB) | 2,149 ms | 2,132 ms | -0.8% |
| GFF, 10,000 records with missing metadata | 1,927 ms | 1,882 ms | -2.3% |
| Packaged protein FASTA | 5.1 ms | 3.3 ms | -35.3% |
| FASTA, 10,000 proteins | 166 ms | 164 ms | -1.2% |
| FASTA, 100,000 proteins | 2,200 ms | 2,038 ms | -7.4% |

The small differences in larger GFF cases and the 10,000-protein FASTA are
within normal timing variability; they provide no evidence of a slowdown.
The 100,000-protein FASTA ranges were 2,098–2,513 ms before and
2,012–2,267 ms after, so its apparent speedup should also be treated cautiously.

| Metadata reshaping only (8 possible fields, sparse records) | Previous | Helper |
| --- | ---: | ---: |
| 1,000 records | 2.15 ms | 0.65 ms |
| 10,000 records | 6 ms | 6 ms |
| 100,000 records | 51 ms | 78 ms |

There is a measurable tradeoff in the isolated 100,000-record metadata test:
27 ms more than tidyr. It did not translate into slower complete file reads in
the tested inputs. These native timings do not predict browser WebAssembly
timings or guarantee identical performance for every metadata layout.

Reproduce from the package root with pkgload, tidyr and Biostrings installed:

```sh
Rscript dev/benchmark-readers.R /tmp/geneviewer-reader-benchmark.csv
```

Use `GENEVIEWER_BENCHMARK_CASES` to select case names with a regular expression.
The benchmark script is excluded from package builds by the existing `^dev$`
rule in `.Rbuildignore`.

Validation
----------

The reader tests and new metadata regression tests pass: 82 assertions,
including complete FASTA reads with Biostrings. Randomized comparison against
tidyr also matched for 120 inputs covering empty input, repeated and missing
keys/values, missing IDs and non-syntactic names. All nine benchmark cases
produced identical outputs. Data files generated by the benchmark are temporary.
The package also installed successfully in a temporary library; a fresh R
session loaded geneviewer and read both packaged GFF and FASTA examples without
loading the tidyr, stringr, stringi or purrr namespaces.
